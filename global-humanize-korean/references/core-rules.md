# 한국어 AI 문체 핵심 규칙

이 규칙은 작성자를 판별하는 기준이 아니라 윤문 후보를 찾는 체크리스트다. 한 표현이 한 번 등장했다는 이유만으로 고치지 않는다. 문맥에 맞지 않거나, 반복되거나, 여러 패턴이 겹쳐 글을 기계적으로 만들 때 수정한다.

## 판단 강도

- **S1 · 우선 수정**: 한국어 문장으로 명백히 부자연스럽거나 의미 없이 붙은 번역투·상투구다.
- **S2 · 반복 시 수정**: 한두 번은 자연스럽지만 한 문서에서 되풀이되면 기계적인 인상을 준다.
- **S3 · 문맥 판단**: 단독으로는 문제가 없다. 리듬과 장르를 해칠 때만 손본다.

## A. 번역투와 피동

다음 표현은 문맥과 반복 횟수를 확인한다.

| 후보 | 자연스러운 방향 |
| --- | --- |
| `X에 대해 논의한다` | `X를 논의한다` |
| `X를 통해 Y한다` | `X로`, `X해서`, 동사로 직접 연결 |
| `X에 있어서` | `X에서`, `X를 볼 때` |
| `X와 관련하여` | `X에`, `X를 두고`, 구체적인 조사 |
| `X에 기반하여` | `X로`, `X를 근거로`, `X를 보고` |
| `경쟁력을 가지고 있다` | `경쟁력이 있다/강하다` |
| `판단되어진다` | `판단된다`, 주체가 분명하면 능동문 |
| `AI에 의해 생성된` | `AI가 만든` |
| `높일 수 있다` 반복 | 사실이면 `높인다`, 가능성이 핵심이면 유지 |
| `X을 위해 Y한다` 반복 | `X하려고`, `X하도록`, 문장 구조 재배치 |

다음 패턴도 함께 확인한다.

- `보여준다·제공한다·가져온다·시사한다`를 추상명사의 만능 동사로 쓰지 않는다. 실제 행위자와 변화를 직접 쓴다.
- `그·그녀·그것·그들`이 한 문단에서 반복되면 생략하거나 사람·팀·제품 이름으로 되돌린다.
- 명사 앞에 긴 관형절이 겹치면 핵심 명사를 먼저 보여 주고 문장을 나눈다.
- `에서의·에로의·으로의·에의·으로부터의` 같은 이중 조사는 절이나 구로 풀어 쓴다. 단순한 `~의`는 자동 수정하지 않는다.
- `회의를 가지다`, `결정을 만들다`처럼 영어의 가벼운 동사를 직역한 표현은 한국어 동사로 되돌린다.

## B. 영어 병기와 전문 용어

- 한글 용어 뒤의 영어 병기는 독자에게 필요할 때 첫 등장에만 둔다.
- API, SDK, prompt, token, framework처럼 업계에서 통용되는 용어는 억지로 번역하지 않는다.
- seamless, robust, leverage처럼 설명 없이 넣은 광고성 영어는 문맥에 맞는 한국어로 풀어 쓴다.
- 코드 식별자, 제품명, 모델명, 라이브러리 이름은 원형을 보존한다.

## C. 기계적인 구조

- `첫째·둘째·셋째`, `먼저·반면·결국`이 매번 같은 순서로 반복되는지 본다.
- 모든 문단이 요약 문장으로 시작하거나 같은 길이의 세 문장으로 끝나는지 본다.
- `A가 아니라 B`, `X에서 Y로`, `A인가 B인가` 같은 대구는 한 번이면 살릴 수 있지만 반복되면 직접 서술로 바꾼다.
- 숫자 목록과 불릿은 비교·절차·조건처럼 나열 자체가 정보를 전달할 때 유지한다. 문장을 잘게 포장한 불릿만 산문으로 합친다.
- 장식용 콜론 제목과 이모지는 장르에 맞지 않을 때 걷어 낸다. 기술 문서와 학술 문서의 실제 절 제목은 보존한다.
- `-고,`, `-지만,`, `-면서,`, `-며,`처럼 연결어미 바로 뒤에 붙은 쉼표는 대개 제거한다.

## D. AI식 상투구와 과장

다음 표현은 삭제가 기본이지만, 원문의 의미를 대신하고 있다면 구체적인 사실로 연결한다.

- `결론적으로`, `정리하자면`, `요약하면`, `이를 통해`
- `시사하는 바가 크다`, `주목할 만하다`, `매우 중요하다`
- `혁신적인`, `획기적인`, `압도적인`, `폭발적인`, `전례 없는`
- `새로운 지평을 열다`, `시대가 도래했다`
- `지금이야말로 ~할 때다`, `~해야 할 시점이다`

상투구를 지운 자리에 원문에 없던 주장이나 수치를 넣지 않는다. 구체적인 근거가 원문에 없다면 군더더기만 제거한다.

## E. 문장 리듬과 말투

- 비슷한 길이의 문장이 계속 이어지거나, 반대로 모든 문장이 지나치게 짧은지 확인한다.
- 같은 종결어미가 네 문장 이상 이어질 때만 문장 구조를 바꾼다. 유의어처럼 종결어미만 기계적으로 교체하지 않는다.
- `~고 있다`가 진행 의미 없이 반복되면 단순 시제로 바꾼다.
- 합쇼체·해요체·한다체를 섞지 않는다. 원문의 주된 말투를 유지한다.
- 살아 있는 감탄, 반문, 구어 종결은 사람다운 흔적일 수 있다. 격식을 높인다는 이유로 없애지 않는다.

## F. 명사화와 중복 수식

- `매우·정말·대단히`와 비슷한 정도부사가 겹치면 필요한 하나만 남긴다.
- `중요하고 핵심적인`처럼 뜻이 겹치는 수식어를 줄인다.
- `~적·~성·~화`가 연달아 등장하면 동사와 형용사로 풀 수 있는지 본다.
- `전략적 함의`, `실천적 기반` 같은 추상명사 사슬은 독자가 실제 행동이나 대상을 알 수 있게 바꾼다.
- `수행 능력`, `추론 능력`, `유지 능력`이 반복되면 무엇을 얼마나 잘하는지 동사로 쓴다.

## G. 불필요한 완곡 표현

- `~할 가능성이 있을 수 있다`, `~로 보여질 수 있다`처럼 완곡 표현이 겹치면 하나만 남긴다.
- 근거가 확정된 사실은 직접 쓴다.
- 전망·추정·불확실성이 본래 의미라면 `~로 보인다`, `~할 수 있다`를 보존한다. 무조건 단정문으로 바꾸지 않는다.
- 정책·안전 문서에서 필요한 신중한 표현은 AI 티로 취급하지 않는다.

## H. 접속사와 메타 문장

- 문장마다 `또한·따라서·즉·나아가·아울러·게다가`로 시작하지 않게 한다.
- 인과와 대조가 문장 자체에서 드러나면 접속사를 생략한다.
- `이는`, `이 점에서`, `이 관점에서`, `이 말은`으로 앞 문장을 반복 설명하는 메타 문장을 본문에 녹인다.
- 접속사를 전부 없애지 않는다. 논리 관계를 오해할 가능성이 있으면 유지한다.

## I. 형식명사와 빈 결말

- `~한 것이다`, `~라는 것이다`, `~라는 점에 있다`는 직접 서술로 바꿀 수 있는지 본다.
- `~할 필요가 있다`, `~해야 한다`가 반복되면 누가 무엇을 하는지 구체적으로 쓴다.
- `것·점·수·바·측면·부분`은 문법적으로 필요한 경우가 많다. 빈 강조나 결말을 만들 때만 수정한다.
- 같은 문단에서 결론을 두 번 말하지 않는다.

## J. 시각 장식

- 본문의 거의 모든 핵심어를 굵게 표시하지 않는다.
- 따옴표는 직접 인용이나 첫 정의에 사용한다. 평범한 단어를 강조하려고 반복하지 않는다.
- 대시와 괄호는 부연이 문장 흐름을 실제로 돕는 경우에만 둔다.
- 원문에 있던 마크다운 링크, 이미지, 표, 코드 블록의 구조는 보존한다.

## 수정하지 말아야 할 것

- 수치, 날짜, 단위, 버전, 고유명사, 제품명, 기관명
- 직접 인용과 사용자가 원문 고정을 요청한 문장
- 코드 블록, 인라인 코드, 명령어, 환경 변수, 파일 경로, URL
- 법률 조문, 각주 정의, 참고문헌, 학술 개념어
- 장르상 필요한 제목, 표, 순서가 있는 절차, 비교 목록
- 한 번만 자연스럽게 등장한 접속사·피동·형식명사
