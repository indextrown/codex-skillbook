# Global Grilling

## 목적

막연한 생각을 곧바로 계획이나 구현으로 바꾸지 않고, 결과를 바꿀 만한 선택을 사용자와 함께 명확히 해요. 질문은 깊게 하되 질문 수를 늘리는 것 자체를 목표로 삼지 않아요. 코드가 없는 아이디어에도, 기존 프로젝트의 설계 결정에도 사용할 수 있어요.

이 스킬은 대화로 결정을 정리해요. 사용자가 별도로 요청하지 않았다면 파일·이슈를 만들거나 계획서·테크 스펙을 작성하거나 구현하지 않아요.

## 진행 방법

1. 사용자가 검토하려는 주제와 이번 대화의 범위를 짧게 확인해요. 이미 정한 목표·제약·선택은 다시 묻지 않아요.
2. 결과에 영향을 주는 결정을 나무처럼 정리해요. 예를 들어 대상 사용자와 성공 조건이 정해져야 기능 범위를 물을 수 있고, 기능 범위가 정해져야 저장 방식의 선택지를 좁힐 수 있어요. 이 나무는 질문 순서를 위한 내부 도구이며, 매번 전체를 출력하지 않아요.
3. 저장소, 제공된 자료나 안전한 조회로 확인할 수 있는 사실은 직접 확인해요. 사용자의 선호, 우선순위, 허용할 절충안처럼 사용자만 정할 수 있는 결정을 질문해요. 확인하지 못한 사실은 가정이라고 밝히고, 그것을 전제로 한 선택을 확정하지 않아요.
4. 선행 결정이 끝난 질문만 한 라운드에 묶어요. 서로의 답에 의존하는 질문은 같은 라운드에 넣지 않아요. 독립적인 질문이 많으면 영향이 큰 것부터 답하기 쉬운 분량으로 나눠요. 사용자가 한 번에 하나씩 묻기를 원하면 그 방식을 따라요.
5. 질문마다 왜 지금 결정해야 하는지 간단히 설명하고 추천안과 그 이유·대가를 제시해요. 추천은 사용자 대신 결정하는 답이 아니에요. 답하기 쉬우면 선택지를 제시하되, 사용자가 다른 답이나 “아직 모르겠어요”를 말할 수 있게 해요.
6. 한 라운드를 물은 뒤에는 답을 기다려요. 답을 받아 확정·보류·변경된 결정을 정리하고, 새로 열린 질문을 다시 계산해 다음 라운드를 진행해요. 이전 답이 바뀌면 그 답에 기대던 결정도 다시 확인해요.

질문 형식은 가볍게 유지해요.

```text
Q1. 알림을 사용자 단위와 프로젝트 단위 중 어디에서 설정할까요?
이 선택에 따라 설정 저장 위치와 화면 구성이 달라져요.
추천: 프로젝트 단위예요. 프로젝트마다 알림 필요성이 다를 수 있지만 설정 화면은 조금 더 복잡해져요.
```

## 멈추는 기준

중요한 선택을 충분히 다뤘거나 사용자가 여기서 멈추자고 하면 질문을 끝내요. 작은 구현 세부 사항까지 끝없이 캐묻지 않아요. 대화만으로 답할 수 없는 문제는 억지로 고르지 말고 필요한 조사나 작은 실험을 제안한 뒤 보류해요.

마지막에는 다음만 간결하게 정리해요.

- 사용자가 확정한 결정과 그 이유
- 아직 검증되지 않은 가정과 보류한 질문
- 다음 단계로 넘길 수 있는 범위

그 요약이 사용자의 생각과 맞는지 확인해요. 사용자가 계획, 테크 스펙이나 구현까지 이미 요청했다면 합의 확인 뒤 해당 작업으로 이어가고, 요청하지 않았다면 대화 결과에서 멈춰요. 답변이 없다는 이유로 결정을 대신 확정하거나 실행하지 않아요.

## 기존 워크플로우와의 경계

`global-grilling`은 결정을 끌어내는 대화예요. 계획 수립, 테크 스펙 작성, 구현은 별개의 결과물이에요. 이 스킬을 다른 스킬의 필수 선행 단계로 만들지 않아요. 사용자가 명시적으로 그릴링을 요청했다면 구체적인 계획에서도 빈틈을 검토해요. 그렇지 않다면 요구사항이 이미 충분할 때 불필요한 질문 세션을 열지 않아요.
