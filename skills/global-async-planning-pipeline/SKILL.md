# Global Async Planning Pipeline

## 목적

구현 전에 Researcher, Planner, Reviewer를 순차 실행해 근거 있는 실행 방향을 정리한다. 서브 에이전트를 실행할 수 있으면 각 역할을 별도 에이전트에 맡기고, 역할별 인계 결과를 다음 역할에 전달한다. 이 스킬은 기본적으로 파일을 수정하지 않고 계획, 근거, 리스크, 검증 방법만 제시한다.

## 사용할 컨텍스트

현재 저장소 또는 작업 디렉터리에서 아래 자료를 가능한 범위로 읽고 적용한다.

1. `AGENTS.md`와 상위·하위 디렉터리의 적용 가능한 지침
2. 아키텍처, 설계, 운영 문서와 관련 코드·테스트·설정
3. 프로젝트에 이미 있는 계획·리서치·리뷰 프롬프트
4. 현재 요청과 대화에서 확인된 목표, 제약, 승인 범위

문서나 프롬프트가 없거나 읽을 수 없으면 파일을 새로 만들지 않는다. 누락된 정보를 명시하고, 확인 가능한 근거만 사용한다.

## 역할별 참조 문서

계획 요청이 트리거되면 아래 문서를 순서대로 읽는다. 단순한 문서 수정처럼 위험이 낮은 요청도 세 단계를 생략하지 않되, 요청 규모에 맞는 깊이로 적용한다.

1. [공통 서술 원칙](references/writing-style.md): 세 역할이 같은 말투, 용어, Markdown 구조로 결과를 작성하게 한다.
2. [Researcher 지침](references/researcher.md): 문제와 근거, 제약, 미확인 사항을 정리한다.
3. [Planner 지침](references/planner.md): 확인된 근거만 사용해 변경 범위와 실행·검증 계획을 만든다.
4. [Reviewer 지침](references/reviewer.md): 계획의 누락과 리스크를 점검하고 다음 상태를 판정한다.
5. [서브 에이전트 오케스트레이션](references/delegation.md): 역할별 실행, 인계, 모델·추론 수준, fallback을 정한다.

## 워크플로우

1. 현재 지침에서 구현 전 승인, 금지 파일, 테스트, 문서화 규칙을 확인한다.
2. [서브 에이전트 오케스트레이션](references/delegation.md)에 따라 실행 가능 여부와 공통 모델·추론 수준을 정한다. 사용자가 이를 지정하지 않으면 현재 부모 에이전트의 설정을 세 역할에 그대로 상속한다.
3. Researcher를 실행하고 Research Packet을 받는다. 서브 에이전트를 쓸 수 없으면 부모 에이전트가 Researcher 지침만 적용해 같은 Packet을 작성한다.
4. Planner에 원래 요청과 Research Packet을 전달하고 Plan Packet을 받는다. 확인되지 않은 정보를 사실처럼 채우지 않는다.
5. Reviewer에 원래 요청, Research Packet, Plan Packet을 전달하고 아래 상태 중 하나로 판정받는다.
   - `Ready`: 실행 전에 해결할 blocker가 없고, 확인된 근거와 검증 계획이 충분하다.
   - `Revise`: 계획을 보완하면 진행할 수 있다. 근거 부족이면 Researcher로, 계획 부족이면 Planner로 되돌린다.
   - `Blocked`: 사용자 결정이나 접근할 수 없는 정보가 없어 진행 방향을 정할 수 없다.
6. `Revise`면 필요한 역할만 한 번 보완한 뒤 Reviewer를 다시 실행한다. 반복해도 해결되지 않으면 `Blocked`로 정리하고 사용자에게 질문한다.
7. 최종 추천 방향, 승인 필요 사항, 다음 단계를 요약한다.
8. 사용자가 구현을 승인하기 전에는 부모와 서브 에이전트 모두 파일 생성, 수정, 삭제를 하지 않는다.

## 출력 형식

아래 형식을 기본으로 사용한다. 각 역할의 상세 필드는 참조 문서의 템플릿을 따른다.

```text
실행 방식: 서브 에이전트 | 단일 에이전트 fallback
서브 에이전트 설정: 현재 설정 상속 | <사용자가 지정한 모델·추론 수준>

## Researcher 관점

## Planner 관점

## Reviewer 관점

## 최종 추천 방향
```

사용자 승인이나 추가 정보가 필요하면 마지막에 이유와 선택지를 짧게 적는다.

```text
위 계획으로 진행해도 될까요? 승인 전까지 파일은 수정하지 않겠습니다.
```

## 금지 사항

- 사용자 승인 없이 파일을 생성, 수정, 삭제하지 않는다.
- 계획 단계의 서브 에이전트에 파일 생성, 수정, 삭제, 커밋, 푸시, 외부 write를 맡기지 않는다.
- `.env`, 인증키, 토큰, 비밀번호, 개인 정보, 배포 서명 파일처럼 민감한 파일을 열람하거나 출력하지 않는다.
- API 계약, DTO, public interface/protocol, DI 구조, 모듈 의존성, 빌드 설정 변경을 가볍게 제안하지 않는다.
- 코드 생성, 의존성 설치, 프로젝트 재생성, 마이그레이션처럼 파일을 만들거나 대량 변경할 수 있는 명령을 승인 없이 실행하지 않는다.
- 확인하지 않은 내용을 프로젝트 사실처럼 단정하거나, Planner의 선택을 Researcher의 근거처럼 표현하지 않는다.
- 코드 변경에 따라 기준 문서, 운영 문서, README, 아키텍처 문서가 달라질 수 있는데도 문서 영향을 생략하지 않는다.
